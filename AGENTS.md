# LochlanProductivity - Agent Instructions

## Project Overview
WinUI 3 / Windows App SDK desktop productivity app (`net8.0-windows10.0.19041.0`, `UseWinUI=true`, `Microsoft.WindowsAppSDK 1.8.260811000`). Focus/anti-distraction: tasks block apps until completed. MSIX packaging enabled.

## Structure
- `LochlanProductivity.slnx` - Solution file
- `LochlanProductivity/App.xaml.cs:7` - App entry, single-instance mutex (`Local\LochlanProductivity.SingleInstance`, relaunch exits), `AppWindow_Closing` hides window instead of exiting to keep blocking alive, `ExitApplication:52` + `ReleaseSingleInstanceLock` for actual quit
- `LochlanProductivity/MainWindow.xaml:4` / `MainWindow.xaml.cs:18` - Main window, all UI logic, task CRUD, blocking UI, dialogs built in code-behind
- `LochlanProductivity/DailyPromptManager.cs:7` - Daily prompt persistence to `%LocalAppData%/LochlanProductivity/daily-prompt.json`
- `LochlanProductivity/Services/` - Core domain:
  - `AppBlockingService.cs` (`Class1.cAppBlockingService.cs`) - process monitoring/killing. `CheckBlockedApps`/`EnforceBlocking` take an effective-apps map (`IReadOnlyDictionary<TodoTask, IReadOnlyList<BlockedApp>>`) and never mutate tasks. Perf: full-path apps share one 2s-TTL process snapshot per tick (re-opened by ID + live path re-verified, so recycled PIDs can't cause wrong kills); kills are never waited on (`WaitForExit` was freezing the UI up to 1s/process/tick) — first sighting sends `CloseMainWindow` + records `StartTime`, later ticks `Kill` past the 1.5s grace (`closeGrace`, pruned)
  - `TrayIconManager.cs` - Shell_NotifyIcon P/Invoke tray icon (Open/Exit), one instance per process
  - `AppGroup.cs` / `AppGroupManager.cs` - app groups (stamped `LastModified` on mutations); default Games/Social groups are empty shells (no hardcoded apps), `availableApps` in `MainWindow.xaml.cs:105` starts empty and is seeded from saved groups/tasks + picker/detect
  - `PolicyManager.cs` - expands groups into effective blocked apps via `GetEffectiveBlockedApps` (pure)
  - `ScheduleManager.cs` / `BlockingSchedule.cs` - scheduled Focus Mode; `WarnMinutesBefore` (default 15, 0 = off) sends a Windows toast (`AppNotificationBuilder`, Reminder scenario, expires at start) via `CheckScheduleWarnings` in the tick (once per occurrence, tracked in `scheduleWarningsSent`); toast click reopens the window; registration failure falls back to the in-app banner. Synced via `MergeSchedules`.
  - `TaskRecurrenceManager.cs` - recurrence (Daily/EveryNDays/WeeklyDays); `CalculateNextDueDate` fast-forwards missed cycles; `CompleteTask` advances recurring tasks
  - `SyncManager.cs` / `SyncData.cs` - two-way merge sync keyed on Id + LastModified for Syncthing-style folder sync; diagnostics in `%LocalAppData%/LochlanProductivity/sync.log` (`SyncManager.Log`: every merge result + failures — Debug.WriteLine is invisible in release, never rely on it); `SyncData.BlockedSites` syncs the website blocklist as a UNION (additions propagate both ways) with removal tombstones (`RemovedBlockedSites`/`RemovedDomains`: `Remove()` records, `Absorb()` skips tombstoned, `AbsorbRemovals()` unions + purges; `Add()` clears the tombstone so re-blocking works); folder configurable via `%LocalAppData%/LochlanProductivity/sync-config.json`, auto-detects Syncthing `config.xml` folders (first is `~/LochlanProductivityData` which you share via Syncthing) then `~/Syncthing/LochlanProductivity` then legacy OneDrive path; atomic `.tmp`+Move writes; `SyncData.BlockedSites` syncs the website blocklist as a UNION (additions propagate both ways; deletions do not); startup sync and Sync Now are allowed while tasks are incomplete (remote completions never overwrite a local incomplete)
  - `StartupManager.cs` - start-with-Windows: packaged StartupTask API (`LochlanProductivityStartup` TaskId) with HKCU Run-key fallback when unpackaged. CRITICAL: never launch the loose `bin/.../AppX/*.exe` directly — it crashes in the App SDK bootstrap (`REGDB_E_CLASSNOTREG`, no window). Always `Add-AppxPackage -Register` the AppX manifest and launch via `explorer.exe shell:AppsFolder\<family>!App`; the HKCU Run key must use that form (written by `EnsureStartupEnabledAsync` when packaged). CRITICAL #2: plain `dotnet build` does NOT refresh the `bin/.../win-x64/AppX/` layout (verified stale dll) — deploy new code there via `dotnet publish` or by copying fresh binaries over AppX (keep the manifest), then relaunch via identity.
  - `WebsiteBlocker.cs` - `HostsFileBlocker` splices a marked section into the hosts file (domains -> 0.0.0.0); transports in order: direct write → pre-approved scheduled task `LochlanProductivityHosts` (registered once via UAC; runs PowerShell over `~/LochlanProductivityData/hosts-staging.txt`, result in `swap-last-result.txt`) → legacy self-relaunch elevated with `--lp-hostsfile <path>` (handled in `App.OnLaunched` BEFORE the single-instance mutex). `BlockedSitesManager` persists domains to `%LocalAppData%/LochlanProductivity/blocked-sites.json`. Applied/removed only on enforcement-state transitions (`UpdateWebsiteBlockingState`; also called directly from Focus Mode toggle + task checkboxes); stale sections self-heal on launch; diagnostics in `webblock.log`. Each computer applies its own hosts entries - on a new machine, approve the single registration UAC. Raw `tasks.json` Syncthing conflicts (`tasks.sync-conflict*.json`) are merged on next load (newest `LastModified` wins, local incomplete never overwritten)
- `LochlanProductivity/Assets/` - App icons/splash

## Conventions & Gotchas
- **XAML + code-behind only** - no MVVM framework. Dialogs are constructed imperatively in `MainWindow.xaml.cs` (e.g., `ContentDialog`, `StackPanel`, `CheckBox`).
- **Blocking is enforcement-heavy** - `BlockingTimer_Tick:876` every 1s calls `UpdateScheduledBlockingState`, `EnforceBlocking`, `UpdateBlockingStatus`. `HasIncompleteTasks` locks Focus Mode and blocks editing (`OpenBlockedAppsDialog:1351`, `ManageSchedules_Click:1720` deny when incomplete).
- **Duplicate EXP handling** - `EnforceBlocking:909` and `UpdateBlockingStatus:975` deduplicate by `ExecutablePath` (case-insensitive) via `GroupBy`.
- **Persistence** - Tasks: `~/LochlanProductivityData/tasks.json` (`MainWindow.xaml.cs:104`). Daily prompt: atomic write via `.tmp` + `File.Move` in `DailyPromptManager.cs:74`. `Load:97` does NOT overwrite on corrupt file.
- **Additive blocking edits allowed while locked** - `ManageAppGroups_Click`, `EditAppGroupAsync`, and `OpenBlockedAppsDialog` open even with incomplete tasks: new apps/groups/checks are enabled, but removals (per-app Remove, group Delete, unchecking a blocked box via `IsEnabled=false`) are disabled until Focus is off. `OpenEditTaskDialog` stays fully locked.
- **Quick-add group strip** - `TaskGroupStrip` in `MainWindow.xaml` (input row, left of Add): one flat color-dot `ToggleButton` per group (system chrome stripped via per-button `Resources` overrides; full color = on, `0.28` opacity = off, no glyph), color = `AppGroup.Color` if set else stable FNV hash of group Id over a 12-color palette (`GetGroupHex`/`GetGroupColor`), tooltip = name + app count. Selection is sticky across adds and restarts (`AppSettingsManager.StickyBlockedGroupIds`, defaults to Games); `AddTask`/`AddTaskForDailyPromptAsync` apply it via `ApplyStickyBlockingPolicy`. Strip rebuilds at the end of `RefreshTaskList`, so new groups appear automatically.
- **Group colors are user-pickable** - `EditAppGroupAsync` and `CreateNewGroupAsync` both show a 12-swatch picker (`BuildGroupColorPicker`); edit SAVE stamps `LastModified` so renames/colors propagate, and `SyncManager.MergeGroups` merges `Color`.
- **Plan Future Task** - `+ Future` header button (`PlanFutureTask_Click` → `OpenPlanFutureTaskDialogAsync`): left = title + `BuildGroupDotToggle` strip (defaults to sticky set, local copy), right = inline `CalendarView` (Single, `MinDate` today, default tomorrow). One-shot non-recurring `TodoTask`; lands in Coming Up until due.
- **Settings menu** - `Settings` item in the `...` flyout (`SettingsButton_Click` → `OpenSettingsDialogAsync`): app preferences only (startup `ToggleSwitch` wired to `StartupManager` with `DisabledByPolicy` handling + re-entrancy guard; Daily Plan message `TextBox` saved on close + enable switch OFF-locked behind `HasIncompleteTasks`; Notes sticky-note mode switch; Theme radios; Tasks auto-delete toggle), deliberately NOT gated on incomplete tasks. Add future options as new sections; never put blocking config (groups/schedules) here.
- **Auto-delete yesterday's completed** - `AppSettingsManager.AutoDeleteYesterdayCompleted` (default off): `DeleteYesterdayCompletedTasks` soft-deletes completed non-recurring non-longterm tasks with `LastCompletedDate` before today (null dates backfilled to today, never deleted on sight); runs at startup + midnight rollover in `BlockingTimer_Tick` (now `async void`) + immediately when toggled on. Check/uncheck handlers stamp/clear `LastCompletedDate`.
- **First-run consent** - `InitializeAsync` shows `ShowConsentDialogAsync` until `AppSettingsManager.ConsentAccepted` (decline → `ForceQuit`, bypassing the incomplete-tasks quit guard). `...` menu has Export/Import backup (`SyncData` snapshot to user-picked JSON; import replaces after confirm); Settings has uninstall-cleanup (hosts section, DNS policies, helper task, Run key).
- **Task list Markdown round-trip** - `...` → Export/Import Task List: `- [ ] Title (due:, time:, priority:, repeats:, id:)` lines under `## Today's Tasks / Coming Up / Recurring / Long-Term Notes` headers. Import matches by `id` (never resurrects tombstones), creates the rest (sticky blocking + `NextSortOrder`), parses repeats (`Every day`/`Every N days`/day names/`EveryNDays`/`WeeklyDays`); `ParseRepeats` returns true only on real change so clean re-imports report zero updates. Trailing parens without real keys stay in the title.
- **Long-term sticky-note mode** - `AppSettingsManager.UseStickyNoteMode` swaps the rail list for `LongTermNoteBox` (multi-line, `AcceptsReturn`); text persists to `%LocalAppData%/LochlanProductivity/longterm-note.json` (debounced 1.2s + `QueueAutoSync`) and syncs via `SyncData.LongTermNote/LongTermNoteModified` (newest wins; never applied while the box has focus). Rail lists are capped at 240px inner scrollers so Long-term and Coming Up stay on screen together.
- **Calendar month view** - `Calendar` header button (`CalendarViewButton_Click` → `OpenCalendarViewDialogAsync`, read-only): `CalendarView` (Single) with sage density dots via `CalendarViewDayItemChanging` for days with active non-longterm tasks; tapping a day lists due titles (✓/•) + recurrence/time meta. No lock gating (view-only).
- **Soft delete / tombstones** - `TodoTask.IsDeleted` keeps removed tasks in `tasks.json` so deletions propagate through sync; UI/enforcement filter via `ActiveTasks`; tombstones older than 30 days are purged in `LoadTasksAsync`.
- **Sync is pull/push on demand** - task mutations do NOT write the shared `syncdata.json`; "Sync Now" merges (Id + `LastModified`, newest wins per item) and writes back, and launch does a silent merge (`SyncOnStartupAsync`) that only refreshes UI when something changed. No auto-sync on mutations.
- **Save after mutations** - every task add/remove/check/uncheck/edit calls `SaveTasksAsync()` and stamps `LastModified = UtcNow` (merge key for sync).
- **Task planning fields** - `TodoTask.Priority` (`TaskPriority` Low/Normal/High) + optional `DueTimeOfDay`; list sorts incomplete-first, then `SortOrder`, then priority desc, then effective deadline; overdue meta line turns OrangeRed. Edit dialog (`OpenEditTaskDialog`) is denied while tasks are incomplete like all other settings.
- **Drag-drop reorder** - Today cards are `CanDrag`/`AllowDrop` carrying `taskId`/`taskDone` in the `DataPackage`; drops only reorder within the same done/undone group (completed stay bottom), top/bottom half picks before/after, group is renumbered `0..n` with fresh `LastModified` (syncs via auto-push). `TodoTask.SortOrder` (double, default 0) merges in `CopyTaskInto`/equality/conflict-merge; new tasks get `NextSortOrder()` (max+1).
- **Scheduled tasks can be reminders** - `CreateScheduledTaskAsync` has a Blocks checkbox section (defaults to the sticky set, Games fallback); unchecking everything creates a no-block reminder (`BlockedGroups`/`BlockedApps` empty, still must be completed). Existing tasks gain blocking later via their card's blocked-apps button (additive while locked). `Scheduled` is a top header button (moved out of `...`).
- **Planning view** - `Planning` header button toggles `PlanningView` (Row 4) over `MainContentGrid`; hides the Today input, retitles to "Planning". `Services/PlanPage.cs` + `PlanPageManager.cs` (`%LocalAppData%/LochlanProductivity/plan-pages.json`, atomic writes): pages hold ordered dateless non-blocking steps (order IS list order; ▲▼✕ per step; checkbox toggles). Steps never feed enforcement/focus/daily. Sync via `SyncData.PlanPages` whole-page newest-wins + tombstones (`MergePlanPages`); included in export/import; `RefreshPlanningView()` runs alongside `RefreshTaskList()` on merges.
- **Daily prompt is mandatory (personal) / optional (public)** - `DailyPromptManager` tracks `CurrentStreak`/`BestStreak`; `CheckDailyPromptAsync` runs once per calendar day (`ShouldShowPrompt` checks `LastPromptDate` != today) and is **required** — no Skip button, Cancel loops, window is forced visible via `ShowMainWindow`, and `HasIncompleteTasks` includes `IsDailyPlanMissing` so Focus stays `Locked` (blocking + hosts) until today's task is added, even with zero tasks. `InitializeAsync` auto-enables startup via `EnsureStartupEnabledAsync` (which always rewrites the HKCU Run key to the running exe, healing stale Debug paths) so the prompt actually appears at logon. Guarded by `dailyPromptActive` so startup + wake paths can't stack dialogs. `SkipToday` remains in code but is unused. Public builds can switch it off in Settings (`AppSettingsManager.DailyPromptEnabled`, OFF locked behind `HasIncompleteTasks`, message customizable via `DailyPromptMessage`); personal strict builds set `AppSettingsManager.AllowDisablingDailyPrompt = false` to hide the switch and force `IsDailyPromptEnabled` true.
- **Wake from sleep** - `BlockingTimer_Tick` (2.5s) tracks `lastBlockingTickUtc`; a gap > 60s means lid-close sleep (Run key never fires on resume), so it calls `ShowMainWindow` + `CheckDailyPromptAsync`.
- **Dialogs follow the theme** - `CurrentDialogTheme` (Dark when the palette `IsDark`); Settings/Future/Calendar dialogs set it explicitly. All dialog content uses defaults (system-adaptive) or `currentTheme` ink/muted slots — never hardcode text colors in new dialogs.
- **Themes** - `Services/AppTheme.cs` (`AppThemePalette`: Frost light + Tapestry dark-millefleurs, `FromName`/`All` for more). Machine-local `AppSettingsManager.ThemeName` (not synced). Main surface colors come ONLY from `currentTheme` via `TB()` + `ApplyTheme()` (named XAML elements); task cards/buttons/text in `RefreshTaskList` too. Settings has a Theme radio section. To add a theme: new static palette + list in `All`.
- **Custom themes** - `ThemeName = "Custom"` resolves via `ResolveTheme()` → `AppThemePalette.Customized(dict, isDark)` (reflection over `Color` props, Frost fallback per slot; see `ColorSlots` for editor order). Edited in `OpenCustomThemeDialogAsync` (slot list + `ColorPicker` with alpha/hex, dark toggle, reset-to-Frost); saved to `AppSettingsManager.CustomThemeColors/CustomThemeIsDark`. Settings reopens after the editor closes. Nested dialogs always go through `HideDialogAndWaitClosedAsync` first.
- **Strict-mode gates** - Sync Now AND startup sync are allowed while tasks are incomplete (remote completions never overwrite a local incomplete); all settings dialogs share the same lock. Browser closing on block engagement is opt-in (`AppSettingsManager.KillBrowsersOnEngage`, default off) - DNS-policy + hosts make it mostly redundant. Chromium secure-DNS is policy-disabled during enforcement (`BuiltInDnsClientEnabled=0` under HKCU Policies; HKCU\Policies is admin-ACLed so un-elevated writes stage through the helper task via `dns-policy-staging.txt`).
- **No tamper seal** - The old `TamperSeal.cs` (HMAC/DPAPI per-machine key on `tasks.json`) was removed: its `.seal` file synced independently of `tasks.json` via Syncthing and used a machine-local DPAPI key, so cross-device sync ALWAYS tripped a false "tampered" lockdown that froze sync and focus. Do not reintroduce a per-machine seal over a syncthing-synced `tasks.json`.

## What to do when helping
- Prefer `dotnet build` to validate, not `dotnet run` (requires UI thread).
- Keep WinUI threading in mind: `DispatcherTimer`, `ContentDialog.ShowAsync()` needs `XamlRoot`.
- Don't delete `bin/ obj/ .vs/ *.csproj.user` - already gitignored.
- When adding blocking logic, update both `EnforceBlocking` and `CheckBlockedApps` paths.
- Keep `DailyPromptManager` atomic-write pattern for any new JSON persistence.

## Do Not
- Don't change `TargetFramework` / `TargetPlatformMinVersion` without checking WindowsAppSDK compatibility.
- Don't remove `AppWindow_Closing` cancel logic - app must stay alive for blocking.
- Don't bypass `IsFocusModeLocked`/`HasIncompleteTasks` guards.
